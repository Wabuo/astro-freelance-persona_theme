The hero typewriter no longer clips mid-word on touch layouts. The typing script pins an inline `min-width` on the installed-text container to the longest typing item's width (desktop's CLS-guard: desktop renders each item on one line), but the ≤1023px block only overrides white-space — the forced width survived there, made the container wider than the phone, and the hero's `overflow: hidden` then sliced wrapped line tails (visibly: text cut off mid-item, then wrapping to the next line with letters missing — most obvious with the starter sample's "responsive and lightweight theme for resume" item). The mobile block now neutralizes the inline lock (`min-width: 0 !important`, beating the inline style) and pins `overflow-wrap: normal`, so wrapping only happens at spaces and hyphenations — a word is never split, and the longest single *word* of an item must fit the mobile typing size (contract now documented in the template's and consumers' `hero.md`; the starter sample's longest word `lightweight` fits trivially). Desktop behavior is untouched by design: the nowrap mode and the JS lock keep preventing typewriter reflow there.
